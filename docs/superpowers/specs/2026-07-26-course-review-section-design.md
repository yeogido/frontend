# 코스 상세 리뷰 섹션 리팩터링 설계

## 목표

`src/pages/yeogido-course-detail/components/CourseReviewSection.tsx`의 시각적 결과와 캐러셀 동작을 홈의 `ReviewSection.tsx`와 동일하게 맞춘다. 상세 페이지에서는 현재 여기도 추천 코스에 매핑된 리뷰만 표시한다.

## 범위

- 상세 페이지의 리뷰 섹션과 상세 코스 리뷰 데이터 타입만 변경한다.
- `src/components/common`의 공용 컴포넌트는 수정하지 않는다.
- 홈의 `ReviewSection.tsx`는 수정하지 않는다.
- 리뷰 섹션 외 상세 페이지 영역은 수정하지 않는다.
- `전체보기`는 시안과 동일한 버튼 모양만 제공하고 클릭 동작은 연결하지 않는다.

## 구조

`YeogidoCourseDetailPage`는 기존처럼 현재 코스를 `CourseDetail`로 매핑한 뒤 `course.reviews`만 `CourseReviewSection`에 전달한다. `CourseReviewSection`은 전달받은 배열만 렌더링하며 전역 리뷰 데이터나 다른 코스의 리뷰를 직접 참조하지 않는다.

상세 코스의 `CourseReview` 타입에는 `ReviewCard`가 이미지 영역을 렌더링할 수 있도록 `images` 필드를 추가한다. 상세 페이지의 목 데이터도 같은 필드를 제공한다.

## UI와 동작

- 제목은 `최근 여행자들의 후기`, 우측 액션 문구는 `전체보기`로 유지한다.
- 리뷰 카드는 컨테이너 전체 폭을 한 장씩 차지한다.
- 가로 스크롤은 한 카드 단위로 스냅한다.
- 스크롤 위치에 따라 활성 페이지 점을 갱신한다.
- 페이지 점을 누르면 해당 리뷰 카드로 부드럽게 이동한다.
- 리뷰가 둘 이상일 때만 페이지 점을 표시한다.
- 카드의 이미지, 프로필, 닉네임, 메타 정보, 본문, 별점은 현재 코스의 리뷰 데이터에서 가져온다.
- 크기, 간격, 색상, 활성 점 너비는 홈 `ReviewSection.tsx`의 값을 그대로 사용한다.
- 상세 페이지에서 이미 부여하는 `mt-[42px] px-5` 배치는 유지한다.

## 데이터 및 예외 처리

- 빈 리뷰 배열은 오류 없이 빈 캐러셀을 렌더링하고 페이지 점을 표시하지 않는다.
- 이미지 URL이 빈 문자열이면 공용 `ReviewCard`의 기존 회색 이미지 플레이스홀더가 표시된다.
- 컴포넌트 외부에서 다른 코스 리뷰를 합치거나 필터링하지 않는다. 페이지가 선택한 코스의 `course.reviews`가 단일 데이터 원천이다.

## 검증

- 소스 기반 회귀 테스트로 상세 리뷰 섹션이 전달받은 `reviews`를 순회하고 이미지 데이터를 `ReviewCard`에 전달하는지 확인한다.
- 페이지 점이 리뷰 배열을 기준으로 생성되고 복수 리뷰에서만 표시되는지 확인한다.
- `전체보기`에 탐색 핸들러가 연결되지 않았는지 확인한다.
- TypeScript/Vite 빌드와 ESLint를 실행해 타입 및 정적 분석 오류가 없는지 확인한다.
- 브라우저에서 상세 코스 페이지를 열어 제공된 390px 기준 이미지와 리뷰 영역의 카드 폭, 이미지 크기, 간격, 스냅, 페이지 점을 비교한다.
