# 행사 선택 페이지 설계

## 목표

`행사 선택.svg`의 문구, 이미지, 정보 순서, 간격과 상태 표현을 손실 없이 React 페이지로 재구성한다. 검색 결과의 행사를 `+` 버튼으로 선택 목록에 추가할 수 있어야 하며, 선택된 행사가 없을 때는 `행사 등록하기` 버튼을 비활성화한다.

## 범위

- 기존 `/local-recommendation` 지역 선택 화면은 유지한다.
- 새 화면은 `/local-recommendation/event-selection` 경로에 추가한다.
- 실제 행사 검색 또는 등록 API 요청은 구현하지 않는다. 현재 API 엔드포인트와 응답 명세가 없기 때문이다.
- 향후 API 응답을 연결할 수 있도록 내부 데이터 타입, 태그 정규화, 태그-에셋 매핑 경계를 구현한다.
- `YeogidoCourseSearchBar`는 기존 파일에서 직접 import하며 수정하거나 행사 선택 페이지 내부로 복사하지 않는다.

## 레퍼런스 보존 원칙

- 원본 파일: `C:\Users\GYEONGJUN\Downloads\local-recommendation\UMC-여기도 (1)\행사 선택.svg`
- SVG 전체를 고정 폭 배경 이미지로 사용하지 않는다. 검색 입력, 행사 카드, 추가 버튼과 등록 버튼을 실제 HTML 요소로 재구성한다.
- 원본 SVG에 포함된 행사 이미지는 개별 에셋으로 분리하되 재인코딩으로 인한 시각적 손실이 없도록 원본 이미지 데이터를 그대로 사용한다.
- 원본에 표시된 제목, 안내 문구, 행사명, 기간, 장소와 버튼 문구는 수정하거나 생략하지 않는다.
- 스타일은 `src/styles/theme.css`의 기존 색상 토큰을 먼저 사용한다. 원본 색상이 토큰과 일치하지 않을 때만 해당 원본 값을 컴포넌트 범위에서 사용한다.

## 반응형 레이아웃

- 390px SVG를 시각적 기준으로 삼는다.
- 콘텐츠는 `width: 100%`로 320px부터 430px까지 자연스럽게 줄고 늘어난다.
- 좌우 여백과 카드 내부 구성은 원본 비율을 유지하되 텍스트나 버튼이 잘리지 않도록 유연한 영역으로 구현한다.
- 768px 이상에서는 콘텐츠 최대 너비를 430px로 제한하고 중앙 정렬한다.
- 데스크톱 전용 다단 레이아웃이나 정보 재배치는 만들지 않는다.

## 컴포넌트 구조

### `EventSelectionPage`

- 새 경로의 페이지 컴포넌트다.
- 검색어, 검색 결과, 선택된 행사 식별자 목록을 관리한다.
- 검색 결과와 선택 목록 모두 동일한 정규화된 행사 모델을 사용한다.
- 선택된 행사 수를 기준으로 하단 등록 버튼의 `disabled` 상태를 계산한다.

### `YeogidoCourseSearchBar`

- `src/pages/yeogido-course/components/YeogidoCourseSearchBar.tsx`에서 직접 import한다.
- `onSearch(query)`를 통해 검색 태그를 페이지에 전달한다.
- 공용화 작업이나 기존 검색바의 UI 변경은 이번 범위에 포함하지 않는다.

### `FestivalCard`

- 행사 이미지, 행사명, 기간, 장소를 표시하는 반복 UI다.
- 검색 결과에서는 `+` 액션을 표시한다.
- 선택 목록에서는 원본 SVG가 제공하는 선택 상태와 제거 UI를 그대로 표현한다.
- 같은 마크업과 스타일을 검색 결과와 선택 목록에서 재사용한다.

### `FestivalSearchResults`

- 정규화된 검색 결과 목록을 렌더링한다.
- 각 결과의 추가 가능 여부를 선택 목록과 비교해 결정한다.
- 이미 선택한 행사는 중복으로 추가하지 않는다.

### `SelectedFestivalList`

- 사용자가 추가한 행사를 추가 순서대로 렌더링한다.
- 원본 SVG에 제거 액션이 존재하면 해당 행사를 선택 목록에서 제거한다.

## 데이터 경계

향후 API 응답은 다음 내부 계약으로 정규화한다.

```ts
interface FestivalApiItem {
  id: string;
  tag: string;
  title: string;
  period: string;
  location: string;
}

interface FestivalItem extends FestivalApiItem {
  imageSrc: string | null;
}
```

- `tag`는 앞뒤 공백 제거와 영문 소문자 변환을 거쳐 비교한다.
- `festivalAssetRegistry`는 정규화된 태그와 SVG에서 분리한 이미지 에셋의 관계만 관리한다.
- `mapFestivalApiItem(item)`은 API 형태의 항목에 `imageSrc`를 결합해 UI 모델을 만든다.
- 등록되지 않은 태그는 다른 행사 이미지를 임의로 대신 사용하지 않고 `imageSrc: null`로 반환한다.
- 실제 API 명세가 확정되면 API 응답을 `FestivalApiItem`으로 변환하는 어댑터만 추가한다. UI 컴포넌트와 에셋 레지스트리는 변경하지 않는다.

## 현재 데이터 동작

- API 명세가 없는 현재 단계에서는 네트워크 요청이나 임의 엔드포인트를 만들지 않는다.
- SVG 원본에 실제로 표현된 행사 항목만 레퍼런스 카탈로그로 보존한다. 원본에 없는 행사나 값을 목데이터로 추가하지 않는다.
- 검색어는 레퍼런스 카탈로그의 태그와 행사명에 적용한다.
- 이후 API가 연결되면 검색 결과 공급원만 API 응답으로 교체하고, 선택·중복 방지·버튼 상태 로직은 그대로 유지한다.

## 상태 흐름

1. 사용자가 검색바에서 태그 또는 행사명을 제출한다.
2. 현재 공급원이 반환한 `FestivalApiItem[]`을 `mapFestivalApiItem`으로 정규화한다.
3. 검색 결과 카드의 `+` 버튼을 누르면 해당 `id`가 선택 목록에 없을 때만 추가한다.
4. 선택 목록은 추가된 순서를 유지한다.
5. 선택 목록이 비어 있으면 `행사 등록하기` 버튼은 비활성화된다.
6. 선택 목록에 하나 이상의 행사가 있으면 버튼은 활성화된다.
7. 실제 등록 API가 없으므로 활성 버튼 클릭에 외부 요청이나 임의 화면 이동을 연결하지 않는다.

## 예외 및 접근성

- 검색 결과가 없으면 원본 문구가 있으면 그 문구를 사용하고, 없으면 빈 목록으로 유지한다. 새로운 안내 문구를 임의로 추가하지 않는다.
- 모든 행사 이미지에는 행사명을 기반으로 한 대체 텍스트를 제공한다.
- `+` 버튼에는 어떤 행사를 추가하는지 알 수 있는 접근 가능한 이름을 제공한다.
- 비활성 등록 버튼에는 실제 `disabled` 속성을 사용한다.
- 행사 `id`를 중복 방지의 기준으로 사용하고 태그가 같은 서로 다른 행사는 별도 항목으로 취급한다.

## 검증 기준

- `pnpm lint`와 `pnpm build`가 성공해야 한다.
- 320px, 375px, 390px, 430px에서 가로 스크롤과 콘텐츠 잘림이 없어야 한다.
- 768px, 1024px, 1440px에서는 430px 모바일 콘텐츠가 중앙 정렬되어야 한다.
- 원본 SVG와 제목, 안내 문구, 행사 정보, 이미지, 카드 순서, 간격과 버튼 상태를 대조한다.
- 검색 결과에서 행사 추가, 중복 추가 방지, 선택 행사 제거, 등록 버튼 활성·비활성 전환을 검증한다.

## 제외 범위

- 실제 행사 검색 API 호출
- 실제 행사 등록 API 호출
- 서버 오류 또는 로딩 상태
- 기존 검색바의 공용 컴포넌트 이동
- 지역 선택 화면에서 새 경로로 이동하는 흐름 변경
